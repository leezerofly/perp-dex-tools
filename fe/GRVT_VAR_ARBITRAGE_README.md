# GRVT-VAR 价差套利系统

## 📖 概述

这是一个在 **GRVT** 和 **VAR (Variational)** 两个永续合约交易所之间进行价差套利的自动化系统。

### 核心策略

1. **开仓**: 在GRVT下限价单（maker单，获得 -0.001% 返佣），成交后立即在VAR下反向市价单
2. **平仓**: 当综合收益（含手续费和点差）达到阈值时，双边市价平仓

### 手续费结构

| 交易所 | Maker费率 | Taker费率 | 其他成本 |
|--------|----------|----------|---------|
| GRVT | **-0.001%** (返佣) | 0.037% | 无 |
| VAR | 0% | 0% | 点差 (约0.005%) |

## 🚀 快速开始

### 前置要求

- Node.js 14+
- 现代浏览器 (Chrome/Edge/Firefox)
- GRVT 和 VAR 交易所账户

### 第一步：安装依赖并启动服务器

```bash
cd fe
npm install ws
node arbitrage_server.js
```

成功启动后会显示：

```
╔══════════════════════════════════════════════════════════════════╗
║          GRVT-VAR 多会话套利服务器 v2.0                           ║
╠══════════════════════════════════════════════════════════════════╣
║  WebSocket端口: 8765                                             ║
║  ...                                                             ║
╚══════════════════════════════════════════════════════════════════╝
```

### 第二步：打开控制面板（可选但推荐）

直接在浏览器中打开 `arbitrage_panel.html`，点击"连接服务器"。

### 第三步：配置客户端 SESSION_ID

**重要**：每一对 GRVT+VAR 客户端需要使用**相同的 SESSION_ID** 来配对。

编辑 `grvt_client.js` 顶部：
```javascript
// ===== 配置区域 - 修改这里的SESSION_ID =====
const SESSION_ID = 'session1';  // 🔴 修改此ID
// ==========================================
```

编辑 `var_client.js` 顶部：
```javascript
// ===== 配置区域 - 修改这里的SESSION_ID =====
const SESSION_ID = 'session1';  // 🔴 与GRVT相同
// ==========================================
```

### 第四步：注入客户端脚本

1. **GRVT 页面**：
   - 打开 https://grvt.io/exchange/perpetual/XRP-USDT (或其他交易对)
   - 按 F12 打开开发者工具
   - 切换到 Console（控制台）标签
   - 复制 `grvt_client.js` 的全部内容并粘贴执行

2. **VAR 页面**：
   - 打开 https://omni.variational.io/perpetual/XRP (或其他交易对)
   - 按 F12 打开开发者工具
   - 切换到 Console（控制台）标签
   - 复制 `var_client.js` 的全部内容并粘贴执行

### 第五步：启动套利

当控制面板显示 GRVT 和 VAR 都已连接（✓）时，点击"启动"按钮。

或在任一客户端控制台执行：
```javascript
GRVT_ARB.start()  // 在GRVT页面
// 或
VAR_ARB.start()   // 在VAR页面
```

## ⚙️ 配置参数

### 服务器端配置

在 `arbitrage_server.js` 中，每个会话的默认配置：

```javascript
config: {
    symbol: 'XRP/USDT',        // 交易对
    orderSize: 100,            // 每次下单数量
    
    // 收益阈值 (GRVT双Maker策略，成本更低)
    minProfitToOpen: 0,        // 开仓最小净收益率 (0=保本就开)
    minProfitToClose: 0,       // 平仓最小净收益率 (0=可立即平)
    
    // GRVT费率
    grvtMakerFee: -0.00001,    // -0.001% maker返佣
    grvtTakerFee: 0.00037,     // 0.037% taker费用 (备用)
    
    // 订单超时设置
    orderTimeout: 5000,        // 限价单超时(ms)，超时后取消重挂
    maxRetries: 10,            // 最大重试次数
    retryDelay: 500,           // 重试间隔(ms)
    priceOffset: 0.0001        // 重挂时价格偏移(更激进)
}
```

### 通过控制面板修改配置

控制面板支持实时修改：
- 下单数量
- 开仓阈值
- 平仓阈值

## 📊 套利收益计算

### ⚠️ 核心原则：计算完整往返收益

**关键点**：开仓时就必须计算"假设立即平仓"的净收益，确保即使价格不变也能盈利！

### 费用明细 (GRVT双Maker策略 ⭐)

**核心优化**: GRVT开仓和平仓都使用限价单(Maker)，双倍返佣！

| 操作 | 交易所 | 订单类型 | 费用 |
|------|--------|----------|------|
| 开仓 | GRVT | **限价单** | **-0.001%** (返佣) |
| 开仓 | VAR | 市价单 | 约 +0.025% (点差/2) |
| 平仓 | GRVT | **限价单** | **-0.001%** (返佣) |
| 平仓 | VAR | 市价单 | 约 +0.025% (点差/2) |

### 完整往返成本 (双Maker策略)

```
总成本 = VAR点差 - GRVT双返佣
       = 0.05% - 0.002%
       = 0.048%

相比原Taker策略(0.086%)，成本降低了 44%！
```

### 订单重试机制

系统对所有类型的订单都实现了完善的失败处理和重试机制：

#### GRVT限价单重试
1. **超时检测**: 默认5秒未成交则取消订单
2. **价格调整**: 重挂时使用更激进的价格(每次偏移0.01%)
3. **重试次数**: 最多重试10次
4. **兜底方案**: 平仓重试次数用尽后，自动改用市价单确保平仓成功

#### VAR市价单重试
1. **客户端重试**: 提交按钮不可用时自动重试(最多5次)
2. **服务器重试**: 订单提交失败时服务器重新发送指令
3. **超时重试**: 3秒内未收到成交确认则重新发送
4. **状态同步**: 实时同步订单状态，确保不遗漏失败订单

#### 完整订单流程
```
GRVT限价单 → 成交确认 → VAR市价单 → 成交确认 → 仓位建立
     ↓              ↓             ↓              ↓
   超时重试      失败处理      超时重试      失败处理
```

### 状态同步机制

系统会自动检测和同步GRVT的仓位和订单状态：

- **仓位检测**: 每10秒检查是否有持仓仓位，自动解析仓位大小、方向和盈亏
- **订单检测**: 实时监控未成交订单数量和状态
- **状态同步**: 自动更新服务器端的会话状态，确保多客户端一致性
- **容错处理**: 页面刷新后能正确恢复状态，避免重复开仓

### 智能开仓判断

开仓前会检查：
- ✅ 无现有仓位
- ✅ 无未完成的订单
- ✅ 价格条件满足
- ✅ 收益预期为正

### 紧急平仓保护

当订单执行失败时，系统会：
- 🚨 **VAR开仓失败**: 取消GRVT订单，避免单边持仓
- 🚨 **VAR平仓失败**: 自动切换到市价紧急平仓
- 🚨 **超时保护**: 所有订单都有超时机制，防止卡单

### 智能开仓判断

开仓前会检查：
- ✅ 无现有仓位
- ✅ 无未完成的订单
- ✅ 价格条件满足
- ✅ 收益预期为正

这样避免重复开仓和订单冲突。

### 开仓条件

只有当：**交易所间价差 > 完整往返成本** 时才开仓

```
净收益 = 交易所间价差 - 总成本

其中:
- 交易所间价差 = |GRVT价格 - VAR价格|
- 总成本 = GRVT taker费(0.037%) - GRVT maker返佣(0.001%) + VAR点差(~0.05%)
```

### 示例计算 (双Maker策略)

假设：
- 交易数量：100 XRP
- GRVT 买入价：1.9200
- VAR 卖出价：1.9210 (价差 0.052%)
- VAR 点差：0.05%

```
完整往返收益计算:

1. 交易所间价差收益:
   = (1.9210 - 1.9200) × 100 = $0.10

2. 成本计算 (双Maker策略):
   - GRVT开仓返佣: 192.00 × 0.00001 = +$0.00192
   - GRVT平仓返佣: 192.10 × 0.00001 = +$0.00192
   - VAR开仓点差:  192.10 × 0.00025 = -$0.0480
   - VAR平仓点差:  192.10 × 0.00025 = -$0.0480
   
   总成本 = 0.048 + 0.048 - 0.00192 - 0.00192 = $0.0922

3. 净收益:
   = $0.10 - $0.0922 = $0.0078
   收益率 = 0.0078 / 192 = 0.004% ✓

即使只有0.052%的价差，也能盈利！(原策略需要>0.086%)
```

## 🔧 多会话管理

### 添加第二对客户端

1. 修改 SESSION_ID：

```javascript
// grvt_client.js
const SESSION_ID = 'session2';  // 改为 session2

// var_client.js  
const SESSION_ID = 'session2';  // 同样改为 session2
```

2. 在新的浏览器窗口（或不同浏览器）打开 GRVT 和 VAR 页面

3. 分别注入修改后的脚本

4. 控制面板会自动显示新的会话卡片

### 会话命名

服务器会自动生成名称（会话1、会话2...），你也可以使用自定义 SESSION_ID：

```javascript
const SESSION_ID = 'btc-arb';      // BTC套利
const SESSION_ID = 'eth-arb';      // ETH套利
const SESSION_ID = 'account-main'; // 主账户
```

## ⚠️ 注意事项

### 风险提示

1. **网络延迟风险**：本地服务器到交易所有延迟，可能导致滑点
2. **部分成交风险**：GRVT限价单可能只成交一部分
3. **极端行情风险**：剧烈波动时可能来不及对冲
4. **技术故障风险**：断网、服务器崩溃等

### 最佳实践

1. **先小资金测试**：初始使用小数量验证系统正常
2. **监控运行状态**：保持控制面板可见
3. **设置合理阈值**：根据实际点差调整开仓阈值
4. **及时响应异常**：发现问题立即使用紧急平仓

### 常见问题

**Q: 客户端无法连接服务器？**
- 确认服务器已启动（显示"等待客户端连接"）
- 检查端口 8765 是否被占用
- 确认防火墙未阻止本地 WebSocket 连接

**Q: GRVT/VAR 页面脚本不生效？**
- 确保页面完全加载后再注入
- 检查控制台是否有报错
- 尝试刷新页面重新注入

**Q: 两个客户端无法配对？**
- 确认两边使用了**完全相同**的 SESSION_ID
- 检查是否有拼写错误或多余空格

**Q: 订单没有执行？**
- 检查账户是否有足够余额
- 确认交易对页面已打开
- 查看是否有弹窗需要确认
